# クラウド側 → GPU 側（2026-10-08h）: DS pilot は判定 4 FAIL（a33 の事後が二峰）→ p1 を粒子 3000・同じ出発点で回す

`gpu_2026-10-08_ds_pilot_wide.md` を読んだ。

## 何が起きているか

- 0・1・2・2b・3 は PASS（移動 5.9〜6.2 回/次元、maxlogL の幅 0.72）。**FAIL は 4 だけ**で、主因は a33（中央値の幅 1.6 sd）。
- a33 の事後は **+1 付近と −10 付近の二峰**。seed123 は中央値 +0.87（5% 点 −11.4）、seed42 は −8.1、seed7 は −0.07。
  → 3 seed とも両方の山を見ているが、**山への配分（重み）が seed ごとに違う**。混合（移動回数）の問題ではなく、
  1000 粒子では二つの山の重みを安定に推定できていない。
- 箱の端は問題なし（a33 の端 2〜12%、片側 0.20 未満）。DS の箱を広げたこと自体は正しかった。

## 対処: p1 を「粒子 3000・3 seed とも同じ出発点」で回す

p1 は前段の事後で箱を絞った上で、事前分布（β=0）から温度を上げ直す（warm start は初期粒子だけ）。
なので **粒子を増やせば山の重みは p1 で推定し直される**。ただし初期粒子の半分は PREV の MAP の近くから取るので、
seed ごとに自分の pilot を PREV にすると、それぞれの山に引っぱられる。**3 seed とも maxlogL が最大の seed123 を PREV にする**。

1. 先置きしている DS p1（3214-3216、2000 粒子）が走っていれば **qdel**。
2. 次で投げ直す（vancouver 優先）:

   ```
   STAGE=p1 TAG=DS N_PART=3000 N_MUT=100 RUNTAG=wide80_p3k
   PREV=_runs/paper_gateoff/DS_pilot_wide80_seed123   （3 seed とも同じ）
   OVERRIDE='5:-15:20;6:-15:20;19:-15:20'              （pilot と同じ）
   SEED=42 / 7 / 123
   ```

   p1 の箱は pilot の平均 ± 4σ。a33 は seed123 でも sd が大きく、箱 [−15, 20] で clip されるので、二つの山は両方とも残る。

3. 報告では、判定 0〜4 に加えて **a33 < −5 の粒子の割合（下の山の重み）を seed ごとに**出してほしい。

## 判定の読み方（今回の二峰に限って）

- 下の山の重みが 3 seed で **±0.10 以内にそろえば、判定 4 が二峰のせいで FAIL しても先へ進めてよい**
  （中央値は重みが 50% 前後だと山の間を飛ぶので、二峰の成分には向かない指標）。原稿では a33 を「二峰・弱く同定」と書く。
- 重みがそろわなければ止めて報告。
