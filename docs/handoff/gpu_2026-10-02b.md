## 相談したいこと: 受理率 FAIL の原因

手順書 §5 は「粒子数・mutation 数を増やして回し直す」とありますが、**箱が狭いことが主因ではないか**と疑っています。

**箱の端 5% に 10% 超の粒子が積んでいる成分が多い**:

| 条件 | 端に積んでいる成分（割合） |
|---|---|
| DS | **a33 0.71**、a34 0.48、a45 0.33、a14 0.10、a24 0.10 |
| DH | a34 0.24、a22 0.20、a44 0.17、a15 0.10、a35 0.10 |
| CS | a13 0.27、a33 0.17、a12 0.13、a11 0.10 |
| CH | a35 0.11、a34 0.11、a14 0.11、a23 0.10、a24 0.10 |

**DS の a33 が 71%** は、箱 `[1.0, 3.0]` が真の最適を含んでいないことを示していると思います。9 月の CPU
ゲート OFF 再推定でも DS の a33 は −0.86（箱 [−4,8]）/ −0.19（箱 [−15,20]）で、**論文の箱の下限 1.0 の外**でした。

端に張り付くと DE-MC の提案が箱外に出て棄却されるので、**受理率の低さは箱の狭さの結果**という筋が立ちます。
だとすると粒子数・mutation 数を増やしても受理率は上がりません。

ident DH（箱を `[-15, 20]` に上書き、粒子 2000）が終われば、

- 粒子数 1000 → 2000 で受理率が上がるか
- 箱を広げると受理率が上がるか

の 2 つが切り分けられます。出たら報告します。**それを見てから回し直しの設定を決めたい**ですが、
クラウド側に別の見立てがあれば従います。

## 2 つ申し送り

### 1. 判定 3・4 は 1 seed なので実質未検証

pilot は seed42 のみなので、`len(maxll) < 2` で判定 3・4 は自動 PASS になっています。手順書も

### 2. 箱の端に積む成分が判定をすり抜ける

判定が全群 PASS になっても、箱の端 5% に 10% 超が積む成分は残っています。
