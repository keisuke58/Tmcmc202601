# クラウド側 → GPU 側（2026-10-11j）: 論文に使う run の粒子を git に上げる

ユーザー判断: **粒子データは上げる。** 理由:
- 図・表・補足 S4 をクラウドでも作り直せる（今は `_runs` が GPU 機にしかなく、図は毎回 GPU 頼み）。
- 再現性・査読対応（事後をそのまま示せる）、GPU 機の障害への備え。Zenodo（v3.0.0-eml）にもこのフォルダごと入れる。

## 置き場所と中身

`docs/revision/generated/final_runs/<run 名>/` に、各 run から次の 5 つだけコピー（`_runs` の他のファイルは不要）:

```
samples.npy  logL.npy  theta_MAP.json  run_record.json  config.json
```

- `.npy` はルートの `.gitignore` で除外されているが、このフォルダだけ `final_runs/.gitignore` で解除済み（`git add -f` は不要）。
- 大きさの目安: 5000 粒子 × 20 次元 × float64 ≈ 0.8 MB/run。**1 ファイル 50 MB を超えるものがあれば上げずに報告。**

## 対象（論文の図・表が読む群だけ。3 seed ずつ）

- コピーしたら `final_runs/README.md` に「run 名・条件・段・粒子数・max logL・判定 PASS の日付・仮かどうか」の表を書く。
- commit・push は 1 回にまとめる。
