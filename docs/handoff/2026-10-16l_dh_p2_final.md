## 確認 1: p2 は ult と同じ尤度か。範囲を狭めた段で、別の山が隠れていないか
- **尤度は同じ。** 自動通知（gpu_2026-10-15_2c_raw_p2_DH.md・gpu_2026-10-16_DH_ult.md）のとおり、p2 も ult も `data_source=raw`、`two_channel=True`（生きた菌・全菌・生きた割合の 3 通路）、同じ raw_dataset（10 ファイル）。
  違うのは n_mut（p2 120、ult 150）と箱だけ。λψ は estimator の自動の規則（DH 3.0）。run_record の `lambda_ch_effective` は、DH p2 を final_runs にコピーしたら確かめる。
- **p2 は範囲を狭めた段ではない。** 段 (iii) は段 (i) の箱に戻し、端に寄った成分は広げた段（a35 は [-25, 20]、a24 は [-15, 20] など、gate の OVERRIDE）。
  **狭めたのは ult の方**（p2 の事後の平均 ±4 SD を箱にする）。そのため「狭めたせいで山が隠れた」は p2 には当てはまらない。
- **ただし注意。** p2 で seed がそろって見えるのは、事後が広く、各 seed が複数の山をまとめて含んでいるからでもある。
  ult で割れた a13・a22・a24 のうち、a13 は p2 で「同定されていない」（sd/一様 sd 0.80）ので判定 4 から外れている。
  つまり p2 の PASS は「同じ広い分布を 3 seed が再現した」という意味で、「山が 1 つ」という意味ではない。本文では、DH の事後は広く、ult まで絞ると seed で山が分かれる、と書く。

## 確認 2: p2 の Pg の D21/15 は seed 間でそろっているか
- **そろっていない。** MAP（max logL の粒子）での D21/15 は seed123 **9.6**、seed42 **13.5**、seed7 **18.0**（実測 14.9、gpu_2026-10-15_2c_raw_p2_DH.csv）。ult の 11.5 / 13.7 / 18.9 と同じくらい割れている。
- 読み方: D21/15 は尤度がほとんど決めない量（logL の差は 0.4 以内なのに、比は 2 倍違う）。ult の FAIL の症状として書くより、**DH では Pg の D21/15 がデータで決まらない**（3 seed の MAP で 9.6〜18.0、実測 14.9 はその中）と書く方が正確。
- 本文に出すときは、seed の MAP の値ではなく、3 seed を合わせた事後の帯（粒子 200 本の 5–95%）にする。粒子が final_runs に来たらクラウド側で計算する。
