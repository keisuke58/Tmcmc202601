# クラウド側 → GPU 側（2026-10-11l）: DH p2 を 20000 粒子で回し直す（p14k は判定 4 だけ FAIL）

`gpu_2026-10-11_gate_DH_ult.md` を読んだ。`DH_p2_nonarrow_w3_noph_p14k` は判定 0〜3・2b は PASS、端の印 0、
**判定 4 だけ FAIL**（中央値幅/sd: a22 0.64・a35 0.60・a45 0.57。a35 は 3 seed とも負の側の 1 つの山で、多峰ではない）。
DS が 12000 → 18000 で通ったのと同じ扱い（10-09e「判定が通るまで回す」）で、**粒子を増やす。箱は変えない**（片側の端はどれも 0.20 未満）。

```
STAGE=p2 TAG=DH SEED=$S N_PART=20000 N_MUT=120 RUNTAG=nonarrow_w3_noph_p20k
OVERRIDE='12:-15:20;5:-15:20;6:-15:20;18:-15:20;13:-15:20;0:-5:5;11:-8:3;19:-5:20;1:-5:3;2:-5:5;7:-10:5'
PREV=_runs/paper_gateoff/DH_p1_mut80_seed$S
```

- seed 42・123・7。**walltime 48h**（p14k の約 1.4 倍の見込み。足りなければ qalter）。4090 優先、DS ult（3371-3373）と枠が競合するなら DS を先に。
- gate（09c 版、MODES なし）を同じ形で仕掛ける。ult は `N_MUT=150 RUNTAG=nonarrow_w3_noph_p20k_sd4`、OVERRIDE 同じ。
- 20000 でも判定 4 だけ FAIL なら、止めて報告（`mode_split_check.py` で a22・a35・a45 を見る。次は粒子でなく山の構造を疑う）。
- 図・final_runs の DH（仮）は、ult が判定を通ったら置き換える。
