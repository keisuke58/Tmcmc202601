## 3. 判定 5 を「磨いた max logL」で読み直す（新規）

`tools/polish_max_logL.py` を追加した。各 run の上位 20 粒子から尤度を L-BFGS-B で局所最大化し、
磨いた値どうしで判定 5 を読み直す。

- 尤度は `run_record.json` の実効値（sigma_obs・phi_init・psi_fixed・K_hill・lambda など）から組み直す。
  **最大化の前に、上位 200 粒子で保存 logL を再現できるか確かめ、再現できなければ止まる**
  （こちらの試験 run では max|差| = 0.0）
- 上位 20 粒子は、まとめて 1 回の L-BFGS-B で磨く（目的関数は粒子ごとの和、評価は vmap 1 回）
- L-BFGS-B が収束していない run がある群は判定しない（「保留」と出る。`MAXITER` を上げて回し直す）
- 対象は ψ 固定・単一チャネルの run（pilot / ident）だけ

```bash
cd ~/Tmcmc202601
qsub -l nodes=1:ppn=1:gpus=1:stuttgart02 -l walltime=08:00:00 \
     -v RUN_GLOB='DH_ident*mut80*',LABEL=dh_ident tools/polish_max_logL_job.sh
```

結果は `docs/handoff/gpu_<日付>_polish_dh_ident.{md,json}` に自動で push される。
ODE を通した勾配なので、CPU では 1 回 2 秒（500 ステップ）かかる。GPU での速さはまだ測っていないので、
walltime は余裕をみて 8h にした。出力の先頭に `JAX devices` が出るので、GPU で走っているかはそこで確かめる。

**読み方:**
- 磨いた値で PASS（prior0 ≥ prior6 − 0.5）→ 同じモードに届いている。判定 5 の差は体積の効果
- 磨いた値でも FAIL → 事前分布なしは主要なモードに届いていない。mutation か粒子数を上げて回し直す
