# クラウド側 → GPU 側（2026-10-12g）: DS・DH の予備を 6 本（本線が落ちたときの待ち時間を減らす）

ユーザー判断（2026-10-12）: 本線が判定に落ちたとき、そこから回し直すと数日失うので、**本線と別の設定の予備を先に走らせておく**。
本線が通れば予備は使わない（消さずに残す。改訂で感度として使える）。

## 1. DS 予備: ult を mutation 多めで（本線 3384-3386 が判定 3・4 で落ちたとき用）

```
STAGE=ult TAG=DS SEED=$S N_PART=18000 N_MUT=250 RUNTAG=wide80_p18k_wide2_sd4_p18k_m250
OVERRIDE='5:-15:20;6:-15:20;19:-15:20;14:-5:4;12:-5:3;16:-5:2.5'
PREV=_runs/paper_gateoff/DS_p2_wide80_p18k_wide2_seed$S
```
- 12b の診断（磨くと幅 0.13 = 探索不足）に対し、粒子ではなく mutation 回数で効かせる版。

## 2. DH 予備: p2 を 25000 粒子で（本線 3395-3397 が判定 4 だけで落ちたとき用）

```
STAGE=p2 TAG=DH SEED=$S N_PART=25000 N_MUT=120 RUNTAG=nonarrow_w4_noph_p25k
OVERRIDE='12:-15:20;5:-15:20;6:-15:20;18:-25:20;13:-15:20;0:-5:5;11:-8:3;19:-5:20;1:-5:3;2:-10:5;7:-10:5;10:-8:3'
PREV=_runs/paper_gateoff/DH_p1_mut80_seed$S
```
- 箱は本線 w4 と同じ。gate（`N_PART=25000`、ult `RUNTAG=nonarrow_w4_noph_p25k_sd4`、N_MUT 150）も同じ形で仕掛ける。
- 本線 w4 に**端の印**が出たら、この予備も同じ箱なので意味がない → その場合は予備を qdel して、印の成分を広げた箱で投げ直す（報告して）。

## 3. 投入先と順番

- **今の本線（DS ult・DH p2 w4）は止めない・優先。** 予備は DH 仮 ult（3388-3390、stuttgart）が終わって空いた 3090 に入れる（`afterany:3388:3389:3390` の依存でよい）。
- 3090 は 4090 より遅いので walltime は長めに: DS 予備 48h、DH 予備 72h（足りるか分からなければ、本線の実測 × 1.5 で決める）。
- 本数: 計算 9 ＋ 予備 6 = 15（上限ちょうど）。gate・通知は数えない。超えそうなら DS 予備を先、DH 予備は後。
- 投入したら jobid とノード、walltime を push。
