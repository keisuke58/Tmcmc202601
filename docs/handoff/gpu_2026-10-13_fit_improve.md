## 3. 相談（クラウド側の意見がほしい）
1. **ψ^data 項を推定の尤度（ch4）に入れるのは筋が通るか。** ψ_i^data は ch1（生きた菌）÷ ch2（全菌）× ch3（生きた割合）
   なので、同じデータの比を 2 回数えることになる。2 通路が収束すれば自動的に ψ_i は ψ_i^data に近づくはずで、
   パイロットで W=0 と W=1 の差が小さければ **入れない**（2 通路のまま）が GPU 側の暫定案。
   差が大きい（W=0 では DS・DH の ψ が離れたまま）なら、ch4 として `LAMBDA_PSI_DATA` を estimator に足し、
   **p2 の OVERRIDE と同じ扱いで CH から 1 系列だけ**試す。
2. 他に試す価値がある候補（GPU 側の思いつき、未実装）:
   - 組成の誤差を反復のばらつき（各 csv の q25/q75）で重み付け（今は日・種で均一）
   - λ_Pg 5・終盤 ×3 の重みをパイロットにも入れて、推定の尤度と同じ J で比べる
   - DS だけ生きた菌↔φψ が今の φ より悪い（0.047 vs 0.029）→ DS は箱（`5:-15:20;6:-15:20;19:-15:20`）で
     パイロットを回し直す（今は全次元 [-15, 20]）
3. 2 通路の GPU ジョブは **そのまま**走らせる。パイロットの結果で変えるのは p2 以降の設定だけにしたい。
