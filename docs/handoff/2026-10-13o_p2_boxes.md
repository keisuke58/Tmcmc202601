# クラウド側 → GPU 側（2026-10-13o）: raw の p2 の箱（CH・DS・DH）。CS は λψ の確認が終わるまで保留

13n で保留にした raw の p2 の箱。根拠はクラウドの CPU（2 通路・raw の尤度を決定論的に最小化した点が箱の端に
張り付いた成分、`docs/revision/generated/two_channel_pilot/raw/`）。張り付いた側だけ広げた
（下限 −1 → −5、−0.5 → −5、−5 → −10、上限 1.5 → 5）。それ以外は 13b の p2 の OVERRIDE のまま。

|---|---|---|
| CH | `1:-5:2.5;11:-5:1;16:-5:1;0:-5:1.5;`**`6:-5:1;7:-1:5;13:-5:1;14:-5:1.5;17:-5:1;18:-5:1`** | a34・a24・a55・a25・a35 が下限 −1、a44 が上限 1.5（13m の新しい σ で） |

## 進め方
- p1 の判定（polish → check）が通ったら、上の OVERRIDE で p2 を投入。粒子数・mutation・walltime は 13b と同じ。
  `DATA_SOURCE=raw TWO_CHANNEL=1 RUNTAG=2c_raw`、13m の作り直しの後（p2 のログの `σ_viab` が CH 0.095・DS 0.059・DH 0.075）。
- **p1 の判定で別の成分に端の印が出たら**、その側も同じ規則で広げて足す（報告に書く）。
  GPU の pilot の通知では DH で a24・a35・a45 が端の 5% に 16〜48%（どちら側かを p1 の判定で確認）。
- gate（p2 → ult）は今までどおり `gate_submit_ult.sh` に `TWO_CHANNEL=1 DATA_SOURCE=raw`、`gpus=1`、DS・DH は `N_PART`。
- 13l の cold p2（CH、`P2_COLD=1`）も上の CH の OVERRIDE で同時に投入してよい。
- 箱を広げると p2 の段数が増えるかもしれない。walltime が足りなければ報告（延長はクラウドとユーザーで判断）。
