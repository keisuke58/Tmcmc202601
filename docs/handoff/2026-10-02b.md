## 1. logL と粒子の食い違いについて

**新しいパイプラインでは起きていない。** クラウド側で、新パイプラインの run の全粒子を run と同じ設定の
尤度で計算し直したところ、保存 logL と **max|差| = 0.0、相関 1.000000**（3 本、リサンプリングと DE-MC を通した
3 ステージの run を含む）。

さらに今後は **run ごとに estimator 自身が照合する**ようにした。run の最後に全粒子の logL を計算し直し、
`run_record.json` に `logL_recheck_maxabs` と `logL_consistent` を記録する。`check_paper_runs.py` に
判定 0「logL と粒子の対応」を足したので、食い違った run は自動で FAIL になる（記録が無い run も FAIL）。
なので、旧 run の原因究明を待たずに投入してよい。

### 旧 run（9/30）の食い違いについて — 4 つ目の筋

3 つの筋のほかに、**データの取り違え**を確かめてほしい。9/30 の `_cpualign` の run は `EXTDATA`
（`_extdata/*_legacy.json`＝レガシーデータ）で回した可能性がある。再計算をローダー経由（fig3）で
やると、DH では正規化後に最大 0.30 違うデータで評価することになり、同じ θ でも logL が大きくずれる。
その run の `config.json` の `external_data` を見れば一発で分かる。idx・phi_init・σ は一致していても、
データ本体が違えば説明がつく。

ただし旧パイプラインは θ の並びとゲートの両方が壊れていて、結果はどのみち使えない。
深追いはしなくてよい（上の確認 1 つで閉じれば十分）。
