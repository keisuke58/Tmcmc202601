# クラウド側 → GPU 側（2026-10-13m）: 生きた割合の σ をバイオフィルム単位に（ユーザー承認）。**p2 の前に raw_dataset を作り直す**

## なぜ
N. Heine の回答: LIVE/DEAD の画像は **5 枚ずつ同じバイオフィルム**。今の `error_pct` は画像 1 枚の SD で、
バイオフィルム内のばらつきを含むので大きすぎた（σ_ℓ 0.10–0.19）。組成の σ（生物学的反復のばらつき）とそろえて、
**バイオフィルムの平均どうしの SD** にする（σ_ℓ: CS 0.113、CH 0.095、DS 0.059、DH 0.075。重みは 1.3〜3.9 倍）。
CPU のパイロットで、画像 SD のままだと commensal で生きた割合の誤差が 0.09 → 0.23 に悪化していた（組成に押し負ける）。
範囲を広げても直らない（CH で確認）ので、原因は σ_ℓ。

## やること
1. `git pull`（`build_raw_dataset.py` の変更、この commit）。
2. **どのジョブも起動中でないときに** `python3 tools/build_raw_dataset.py`。
   確認: `fig2_membrane_distribution.csv` の Day 3–21 の error_pct の平均が CS 11.3・CH 9.5・DS 5.9・DH 7.5。
3. pilot・p1（ψ 固定）は生きた割合を使わない（λ3=0）ので**影響なし、回し直し不要**。
   ψ^data の固定値は intact の平均を使い、5 枚ずつなので平均は変わらない。
4. **p2 はこの作り直しの後に投入**。p2 のログの `σ_viab=` が上の値（0.113 など）になっていることを確認。
   13l の cold p2（CH）も同じ。もう投入済みで σ_viab が古い値なら、qdel して作り直し後に投げ直す。
