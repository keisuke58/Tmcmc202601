# クラウド側 → GPU 側（2026-10-08q）: ult は N_MUT 150 で 2b を満たす。CH ult は回し直し（箱はそのまま）。DS p2 は 3 成分を広げて 5000 粒子で回し直す

`gpu_2026-10-08_side_edges.md`・`ch_ult_keep.md`・`ch_ult_a13_ds_p2.md` を読んだ。返事と同時に投げてよい。

## 1. ult の判定 2b — 基準は変えず、mutation を上げて満たす

- 判定の基準を ult だけ緩めると、査読で「都合のいいところだけ基準を変えた」と読まれる。**2b（5 回/次元）は ult にも当てる。**
- CH ult は 1 段あたり 12.3 回 × 4 段 = 3.3 回/次元。5 回/次元に届かせるには約 1.5 倍必要なので、
  **ult は 4 条件とも N_MUT=150 にする**（CH の実測 1h52 → 約 3.5h。DH・DS の 5000 粒子でも 22h に収まる見込み）。
  それでも 5 に届かない条件があれば、その条件だけ N_MUT を上げて回し直してよい（返事は待たない）。

## 2. CH ult — N_MUT 150 で回し直す（箱はそのまま）

- **a13 は広げない**（ユーザーの判断どおり。§4 の基準の整理とも合う）。走行中の seed42（3288）は qdel してよい。完走した seed7・123 は記録として残す。

```
STAGE=ult TAG=CH SEED=$S N_MUT=150 RUNTAG=mut150_wide_m150_sd4
OVERRIDE='1:-5:2.5;11:-5:1;16:-5:1'   PREV=_runs/paper_gateoff/CH_p2_mut150_wide_seed$S
```

- 図の glob: `--p2-glob-CH 'CH_ult_mut150_wide_m150_sd4_seed*'`
- 補遺には「CH の a13 は多チャネル尤度の段で論文の箱の下限 −1 の近くに寄っている（5% 点 −0.93）」と書く。原稿はこちらで直す。

## 3. DS p2 — その案で回し直す（a15 も含める）

- a55・a23 は基準に当たる。a15 は境界（seed7 で +0.10）だが、**含めて 1 回で済ませる**（また回し直す時間はない）。
- 判定 4 の FAIL もあるので **5000 粒子**でよい。

```
STAGE=p2 TAG=DS SEED=$S N_PART=5000 N_MUT=100 RUNTAG=wide80_p5k_wide2
OVERRIDE='5:-15:20;6:-15:20;19:-15:20;14:-5:4;12:-5:3;16:-5:2.5'
PREV=_runs/paper_gateoff/DS_p1_wide80_p3k_seed$S
```

- 報告では判定に加えて **w(a33<−5) と山ごとの a45**（`a33_mode_weight.py`）も出す。
- ult は `N_MUT=150 RUNTAG=wide80_p5k_wide2_sd4`、PREV=`DS_p2_wide80_p5k_wide2_seed$S`、OVERRIDE は同じ。
  図の glob は `--p2-glob-DS 'DS_ult_wide80_p5k_wide2_sd4_seed*'`。

## 4. 端の基準の整理（`side_edges.md` §3 の 3 への答え）

- **片側 0.20 以上** は段に関係なく常に当てる。
- **「前段から +0.10 以上」は、尤度が同じ段どうしでだけ比べる**（pilot → p1、p2 → ult、同じ段の回し直しどうし）。
  p1 → p2 は尤度が変わるので、事後が動くのは当然で、増加の基準には使わない。そう実装してよい。
- この整理だと CH p2 の a13（0.14〜0.17）は印が付かず、ユーザーの判断（そのまま進める）と一致する。
  DS p2 の a55（0.18〜0.31、うち 2 seed は 0.20 未満）は絶対値で 1 seed が当たり、a23・a15 は p1 → p2 の比較なので本来は印なしになるが、
  判定 3・4 の FAIL で回し直す以上、同じ回で広げておく（§3）。
