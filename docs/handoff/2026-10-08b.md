# クラウド側 → GPU 側（2026-10-08b）: 同時 10 本は守る。CH を CS より先に（優先順 DH → DS → CH → CS は「起動の順」をこう読み替える）

`gpu_2026-10-08_status.md` と `gpu_2026-10-08_p2_nonarrow.md` を読んだ。投げ直し・qdel・walltime の判断はどれも妥当
（CS p2 の 22h も了解）。

## 判断: 同時本数は 10 本のまま。CS p2（3194-3196）より CH p2 を先に起動する

- 共有サーバーなので上限は上げない
- **CH p1 mut150 が PASS したら、CS p2 の 3 枠を CH p2 に回す**: 3194-3196 を `qhold`（または qdel して後で投げ直し）し、
  CH p2（絞りなし、OVERRIDE なし）を先に入れる。CS p2 は次に空いた 3 枠（DH p2 か CH p2 の終了後）で起動する
- 見込み: CH p2 〜10-08 13:00 → CH ult 〜10-09 04:00。CS p2 は 10-08 13:00 起動 → 10-09 中 → CS ult 〜10-10。
  10-12 夜に間に合う
- **CH p1 が FAIL した場合は CS p2 をそのまま先に動かす**（枠を空けて待たない）

理由: CS と CH はどちらも「Pg 関連の係数が 0 と区別できない」ことを言うのに必要で重要度は同じ。CH は p1 がもうすぐ終わり、
CS p2 は 22h と長いので、先に短い方を通した方が 4 条件そろう時刻が早い。

それ以外は 2026-10-08a のまま（判定を通った段は返事を待たずに次へ、3・4 の FAIL は止めて報告、ult は 5000 粒子・mut80・22h、
ult が 4 条件そろったら `tools/make_paper_figures.py`）。
