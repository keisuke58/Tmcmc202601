# クラウド側 → GPU 側（2026-10-16e）: **DS の p2 が出力なしで終わっている**。最優先で原因を調べて出し直す。CH の磨き直しはそのまま

## 1. 何が起きているか（push された報告から）
- DS p2 の磨き 3597〜3599（10:07 JST）がすべて `対象の run が無い: _runs/paper_gateoff/DS_p2_2c_raw_seed{42,7,123}` で終わっている
- そのあとの gate 3600 も `前段の run: 0 / 3`、`run が無い` で ult を投げていない（175ddc5）
- DS p2 3519〜3521 は qstat に無い。10/14 夕方に walltime **40h** で投入 → 10/16 10:07 JST ごろ終わった計算なので、
  **walltime 切れで、最後に書く出力ディレクトリが作られなかった**可能性が高い（箱を広げて段数が増えると足りないかも、と 10/14 に心配していたとおり）

## 2. やること（この順で、DS が最優先）
1. `logs/pbs/` の 3519〜3521 のログで、終わり方（`walltime ... exceeded` か crash か）・到達した段（stage と β）・1 段の時間を確認
2. 途中の段から再開できる保存（checkpoint）があるか確認。無ければ最初から
3. DS p2 を出し直す。walltime は「到達した段 × 1 段の時間」から必要な段数（β=1 まで）を見積もって **× 1.5**（上限があればそれ。足りなければ 4090 の空いたノードに）。
   設定は前回と同じ（18000 粒子 × 150、13o の DS の OVERRIDE、`DATA_SOURCE=raw TWO_CHANNEL=1 RUNTAG=2c_raw`、PREV=`DS_p1_2c_raw_seed<S>`）。
   段数を減らす工夫（粒子・mutation を減らす）は**しない**（前回の判定と比べられなくなる）。walltime を延ばすだけ
4. 磨き（16b の設定）→ gate（`POLISH=0`）→ ult を、前と同じく依存でつなぐ。ult の walltime も DS p2 の実測から見積もり直す（36h で足りるか）
5. 報告: 1 の結果と、出し直したジョブ・walltime・終わる見込み
