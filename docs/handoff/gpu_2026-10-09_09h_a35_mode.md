**walltime を 22h → 30h にして投げ直した（ユーザー指示）。** 見積もり 20.6h に対して 22h では余裕が 1.4h しかなかったため。
実行中の walltime は `qalter` で延ばせない（`Unauthorized Request`）ので、最初の 3346-3348（約 10 分走行）と gate 3349 を qdel して投げ直した。
このとき 3349 が依存の解除で一瞬起動し、前段 0 本のまま「判定が通らず投入せず」を `gpu_2026-10-09_gate_DH_ult.md` に上書きして push した（dde4307）。

## 2. a35 の山の診断（09h §1、`tools/a35_mode_weight.py`）

対象は `DH_p2_nonarrow_w2_noph_p10k_seed{42,7,123}`。3 seed 合算の a35 のヒストグラムは
**−13 付近の鋭い山と −3 付近の主峰の二峰**で、谷の底は −11〜−9.6。しきい値は谷の **−10** を本命にし、09h の目安 −7 も並べた。

### 山の重み（seed ごと）

| seed | w(a35 < −10) | w(a35 < −7) | a35 中央値 | a35 5% / 95% | max logL |
|---|---|---|---|---|---|
| 42 | **0.596** | 0.727 | −11.80 | −13.33 / −2.36 | −15.08 |
| 7 | **0.053** | 0.134 | −3.62 | −10.16 / −1.37 | −14.88 |
| 123 | **0.120** | 0.382 | −5.99 | −11.73 / −1.55 | −15.26 |

**山の重みは seed 間で ±0.10 にそろっていない**（−10 で 0.05〜0.60、−7 で 0.13〜0.73）。
08h の規則（下の山の重みが ±0.10 でそろえば判定 4 の FAIL は二峰のせいとして先へ）は、この 10000 粒子では満たさない。

- **山ごとの max logL の差（上 − 下）は −0.04 / +0.70 / +0.20 で、全部 1 未満** → 09h の基準では「データでは区別できない 2 つの山」。
- **a45 は下の山（a35 < −10）で 3 seed とも正**（中央値 +2.2〜+4.6、5% 点も正）。上の山（主峰）は中央値 +0.06〜+2.10 で、seed 42・7 では 5% 点が負。
  つまり a45 > 0 の強さは a35 の下の山と組になっている。DH の a45 の中央値が seed で揺れる（+0.14 / +2.1 / +2.7）のは、この山の配分の違いでほぼ説明できる。
- しきい値 −7 でも傾向は同じ（下の山の a45 中央値 +3.21 / +2.02 / +2.26、max logL 差 −0.04 / +0.59 / +0.20）。全文は下。

### 合算ヒストグラムで気づいた点

- **a45 は 15〜16 に 2302 粒子の鋭い山がある。** 内訳は seed 42 が 2340、seed 7 が 3、seed 123 が 0。
  seed 42 のこの粒子は a35 の中央値 −13.2 で、−13 付近の a35 の鋭い山と同じ粒子の塊。2331 個が別々の点なので、重複粒子の偏りではない。
  **seed 42 だけが (a35 ≈ −13, a45 ≈ 15) の副峰を大きく拾っている**。a45 の箱の上限は 20 なので、端に張り付いているわけではない。
- a25 は 1.5〜1.6、a22 は −1.0 付近と −0.4〜−0.1 にやや尖った bin がある（全体は幅広い）。
