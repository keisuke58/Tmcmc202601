# クラウド側 → GPU 側（2026-10-07h）: DS の箱を広げた pilot（3172-3174）が出力なしで終わった

## 何が起きたか

通知 3178 が 23:22 に発火した（`gpu_2026-10-07_ds_pilot_wide.md`）が、`DS_pilot_wide80_*` の出力ディレクトリが **0 個**。
投入は 22:30 頃なので、**3 本とも 1 時間足らずで終わっている**。pilot は通常数時間かかるので、途中で落ちたと見ている。
estimator は出力ディレクトリを最後（`estimate_paper_jax.py` の `out_dir.mkdir`）に作るので、途中で落ちると何も残らない。

## 調べてほしいこと（ログの末尾を handoff に貼ってほしい）

1. 3172-3174 の PBS ログの末尾 40 行（`paper_gateoff_*.log` か `-o` の出力先）
2. ログに `Override bound [5] -> [-15, 20]`・`[6]`・`[19]` の **3 行がそろって出ているか**
   - 1 行しか無ければ、`qsub -v ...,OVERRIDE='5:-15:20,6:-15:20,19:-15:20'` の**カンマで変数が分割された**のが原因
     （`qsub -v` はカンマで変数を区切る）。`qstat -f <jobid> | grep -A3 Variable_List` でも確認できる
3. それ以外のエラー（GPU のメモリ、Newton の発散、walltime など）

## 直したこと（pull してから投げ直す）

- `paper_gateoff_job.sh` は **`OVERRIDE` の区切りに `;` も使える**ようにした（中でカンマに戻す）。
  投げ直すときは `OVERRIDE='5:-15:20;6:-15:20;19:-15:20'` で渡す。p1 以降の段でも同じ値を渡すこと。

## 投げ直し

- 原因を直したら、**DS pilot wide80 を 3 seed（42 / 7 / 123）で投げ直す**。通知は 3 本すべてに依存させる。
- 締め切りは変わらない（ult を 10-12 夜まで）。DS の pilot → p1 → p2 → ult が間に合わない見込みなら、
  その時点で分かる範囲を報告してほしい（論文では DS を「箱を広げた推定」として段の途中までで報告する手もある）。
