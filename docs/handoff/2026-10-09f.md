# クラウド側 → GPU 側（2026-10-09f）: DS p2（8000 粒子）が 3・4 FAIL → 診断と回し直しを同時に

粒子を 5000 → 8000 にしても落ちる成分が変わるだけ（前回 a22/a14/a13、今回 a34/a45/a24、maxlogL 幅 0.70 → 1.34）。
seed ごとに別の平らな領域に落ち着いているので、粒子数だけでは直らない。

## 1. 診断（CPU・すぐ）

- `polish_max_logL_job.sh`（または同等）で 3 seed の max logL 粒子を磨き、**磨いた後も幅が 1 を超えるか**を見る（超えなければ探索不足、超えれば本当に別の山）。
- 3 seed の MAP（15 成分）を並べて、どの成分がどれだけ違うかを表にする。a45 の 5/50/95% も。
- 3 seed の粒子を合わせて（24000）、a45・a34・a24 のヒストグラムが多峰かどうか（`a33_mode_weight.py` の形で、しきい値はヒストグラムを見て決める）。

## 2. 回し直し（4090 で、N_MUT も上げる）

```
STAGE=p2 TAG=DS SEED=$S N_PART=12000 N_MUT=150 RUNTAG=wide80_p12k_wide2
OVERRIDE='5:-15:20;6:-15:20;19:-15:20;14:-5:4;12:-5:3;16:-5:2.5'
PREV=_runs/paper_gateoff/DS_p1_wide80_p3k_seed$S
```
- 8000 粒子・N_MUT 100 が 4090 で 8.5h → 12000・150 で約 19h。**3090 では 22h に収まらないので 4090 のみ**。
  seed42 は vancouver03 の空き 1 枚に今すぐ。seed7・123 は DH p2（3321-3323）の `afterany` 依存で vancouver に。
- gate（09c 版）を同じ形で仕掛ける。ult は `N_MUT=150 RUNTAG=wide80_p12k_wide2_sd4`。
- §1 で「本当に別の山」と出たら、この回し直しの結果と合わせて原稿側で扱いを決める（止めずに回しておく）。
