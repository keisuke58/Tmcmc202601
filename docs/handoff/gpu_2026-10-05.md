## 2. FAIL 3・4 の原因 = 混合不足。粒子の退化ではない

- unique 粒子は 98.8〜100%（2000 粒子中 1977〜2000）→ **縮退していない**
- 事後 sd / 事前 sd = 0.15〜0.53 → データは効いているが事後は依然広い（箱 35 に対し sd 1.5〜5.8）
- **1 粒子が run 全体で 1 自由次元あたり 1.4〜2.2 回しか動いていない**（15 自由次元、10 ステージ）
- seed ごとに事後 sd 自体が違う（a33 で 2.92 / 3.86 / 1.47）→ 各 seed が別の領域に居座っている

### 実装側の不具合 2 つ

**(a) 低 beta で mutation 回数が 1/3 に絞られていた** — `tmcmc_engine_paper.py`

```python
_n_mut = max(3, int(n_mutation_steps * max(0.3, beta_new)))
```

`--n-mutation-steps 40` でも beta が小さいステージは 12 回しか回らない。**広い探索が必要な
低 beta を狙い撃ちで絞っている**のが問題で、実際に回ったのは 400 回のうち約 174 回（44%）。

**(b) 受理率が名目値で割られていた** — 同ファイル

```python
_n_total_proposals = n_particles * (n_mutation_steps if mutation == "rw" else 1)
```

実際の提案数ではなく名目の 40 で割っていたので、**これまで報告していた「受理率 8% / 6%」は
約 3 倍過小**。低 beta の真の受理率は 0.19 程度。10/2 の「受理率 8% は不具合ではない」という
議論は、この誤った数字の上に乗っていた（結論は変わらないが根拠の数字が違う）。

なお判定 2 は (b) の過小評価と「×40」が打ち消し合って**偶然正しい値**（= 1 粒子の移動回数）を
計算していた。**判定 2 が甘すぎた**のが本質。
