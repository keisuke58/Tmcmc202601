# クラウド側 → GPU 側（2026-10-08r）: pH を推定から外す（ユーザー判断）。DH・CH の p2 と ult を pH なしで回し直す

**`git pull` してから投げること**（job スクリプトを変えた。PBS は qsub 時のスクリプトを使う）。

## なぜ

- いまの p2 / ult は HOBIC で pH を重み 0.3 で尤度に入れている。式は `pH = 7.5 − 0.74·φ̄_So − 0.48·φ̄_Vd`（`estimate_paper_jax.py` 321 行）。
  これは **Heine の pH データへの事後回帰から作った式**（`evaluator.py` のコメント、R²=0.71）で、同じ pH データの尤度に使っている。しかも回帰の切片は 6.95 なのに実装は 7.5 で、理由の記録がない。
- 共著者に回した版では、pH は推定に使わず、**全種の回帰式**（`pH = 6.10 + 0.16 So + 0.55 An + 0.30 Vei + 1.22 Fn + 1.88 Pg`、実測の組成だけで OLS、LOO-RMSE 0.056）で **答え合わせ**していた（R² 0.78）。
- ユーザー判断（2026-10-08）: **pH は推定から外し、全種の式による答え合わせに戻す。**

- 通ったら ult（**N_MUT=150**、OVERRIDE は p2 と同じ）:
  - DH: `RUNTAG=nonarrow_a45_noph_sd4`、PREV=`DH_p2_nonarrow_a45_noph_seed$S`
  - CH: `RUNTAG=mut150_wide_noph_sd4`、PREV=`CH_p2_mut150_wide_noph_seed$S`
- 図の glob:
  ```
  --p2-glob-DH 'DH_ult_nonarrow_a45_noph_sd4_seed*'
  --p2-glob-CH 'CH_ult_mut150_wide_noph_sd4_seed*'
  ```
- 優先: **DH p2 → CH p2 → それぞれの ult** を最優先（本線）。枠が足りなければ λ 感度を qdel して譲ってよい。
- 見込み: DH p2 約 12h → ult 約 8〜10h、CH p2 数時間 → ult 3〜6h。10-10 中に 4 条件の ult がそろう見込み。
