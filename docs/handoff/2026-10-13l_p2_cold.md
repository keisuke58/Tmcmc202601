# クラウド側 → GPU 側（2026-10-13l）: CH の p2 を warm start なしで 1 本（段階分けの偏りの確認、ユーザー承認）

## なぜ
p2 は p1（ψ をデータから固定）の MAP の近くに粒子の半分を置いて始める（`--init-from-dir`）。TMCMC は最初の粒子が
事前分布からの標本であることを前提にしているので、混ざりが足りないと p1 の側に偏る可能性がある。
生データでは p1 で固定する ψ^data の不確かさが大きい（ブートストラップの 90% 区間が 0.5 以上、1 を超える日も）ので、
warm start の行き先が p2 の答えから離れているかもしれない。**事前分布から始めた p2 が同じ事後に行くか**を CH で確かめる。

## 投入（1 本、今の raw の列と独立なのですぐ投げてよい。上限 15 本は守る）
`paper_gateoff_job.sh` に **`P2_COLD=1`** を追加した（この commit。`--init-from-dir` を付けず、PREV も要らない）。
```
qsub -l walltime=16:00:00 -l nodes=1:ppn=1:gpus=1:<空き> \
  -v STAGE=p2,TAG=CH,SEED=42,DATA_SOURCE=raw,TWO_CHANNEL=1,P2_COLD=1,RUNTAG=2c_raw_cold,OVERRIDE='1:-5:2.5;11:-5:1;16:-5:1;0:-5:1.5' \
  paper_gateoff_job.sh
```
粒子数・mutation・箱は 13b の CH p2 と同じ（2000×150。N_MUT=150 を忘れずに）。gate・ult は付けない。
起動したら `run_record.json` の args に `init_from_dir: null`、`data_source: "raw"`、`two_channel: true` を確認。

## 比べ方（warm の `CH_p2_2c_raw_seed42` が出たら）

  （ref = `CH_p2_2c_raw_seed42`、alt = `CH_p2_2c_raw_cold_seed42`）。
- 段の数・計算時間も並べる（warm start の効果の大きさ）。
