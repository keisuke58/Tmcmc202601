# クラウド側 → GPU 側（2026-10-14b）: CH の a33（θ[5]）の下限を広げて p2 から回し直す（ユーザー決定）

[gpu_2026-10-15_ch_a33_weights.md](gpu_2026-10-15_ch_a33_weights.md) §1 への返事。**広げて回し直す**（限界として書くのではなく）。
理由: 補足に書いた規則「片側の外側 5% に 20% より多い → 箱を広げる」に当たる（a33 の下端に 20〜21%、p1 の 12〜13% から強まった）。
CS・DS・DH の p2 はすでに a33 を [−15, 20] にしているので、CH だけ論文の箱（[−1, 1.5]）のまま、という不揃いも解消する。
日程への影響はほぼ無い（DH の p2 48h が律速）。

## 1. 止めるもの
- **gate 3523（CH の polish → ult）と、そこから投げた CH の ult・通知のジョブ**（3524 など、CH の p2/ult に依存しているもの）を `qdel`。
  ult がもう走っていたら止めて、出力ディレクトリは消さずに名前の**先頭に** `aborted_a33_` を付けて残す（`tools/rebuild_eml_raw.sh` の glob `{tag}_ult_2c_raw*_seed*` に引っかからないように）。
- **cold p2（3522、13l）は止めない**。warm と cold の比較は同じ（古い）箱どうしで意味があるので、そのまま最後まで。
- 今の `CH_p2_2c_raw_seed*` は消さない（a33 が端に張り付いた記録として残す。論文の数字には使わない）。

## 2. 投入するもの: CH の p2（3 seed）
- 13o の CH の OVERRIDE に **`5:-15:20`** を足す（CS・DS・DH と同じ）:
  `5:-15:20;1:-5:2.5;11:-5:1;16:-5:1;0:-5:1.5;6:-5:1;7:-1:5;13:-5:1;14:-5:1.5;17:-5:1;18:-5:1`
- `DATA_SOURCE=raw TWO_CHANNEL=1 RUNTAG=2c_raw_a33w`、PREV=`CH_p1_2c_raw_seed<S>`（p1 はそのまま使う。p1 で a33 は 12〜13% で規則に当たらなかった）。
- 粒子数・mutation・walltime は今の CH の p2 と同じ（2000×150、16h）。seed 42 / 7 / 123。
- gate は今までどおり（`gpus=1`、判定前に polish）、`TWO_CHANNEL=1 DATA_SOURCE=raw PREV_RUNTAG=2c_raw_a33w ULT_RUNTAG=2c_raw_a33w`、
  OVERRIDE は上と同じ、ult は前回と同じ設定（5000×150、14h）。通知も今までどおり。
- 投入時の `qstat -f` で OVERRIDE に `5:-15:20` が入っていること、ログの `σ_viab` が 0.095 であることを確認。

## 3. 確認してほしいこと（p2 の通知のとき）
- a33 の事後が下端から離れたか（端の 5% の割合）。広げた先の下端（−15）にまた張り付くなら報告（そのときは数値の不安定でないかも見る）。
- a33 の中央値・90% 区間を、前の p2（[−0.97, −0.67, +0.09]）と並べて。
- `spec_raw.json` の CH の p2・ult は、クラウド側で `CH_p2_2c_raw_a33w_seed*`・`CH_ult_2c_raw_a33w_seed*` に変えた（このコミット）。
