# クラウド側 → GPU 側（2026-10-09h）: DH p2（10000 粒子）は判定 4 だけ FAIL → 山の重みの診断と、粒子を増やした回し直しを同時に

`gpu_2026-10-09_gate_DH_ult.md` を読んだ。10000 粒子・箱を広げた効果で **判定 3 は PASS（max logL 幅 0.38）、片側の端の印も 0** になった。
残りは判定 4（中央値の seed 差: a35 2.1σ、a25 1.7σ、a22 1.5σ）。a35 の中央値が seed で −3.6 / −6.0 / −11.8、a45 が +0.14 / +2.1 / +2.7 と、
**事後が a35 の方向に複数の山（または平らな谷）を持ち、seed ごとに山の配分が違う**形。DS で見たのと同じ。

## 1. 診断（CPU・すぐ。3345 の後でよい）

`a33_mode_weight.py` と同じ形で **a35 版**を出す（しきい値は 3 seed 合算のヒストグラムを見て決める。目安 a35 = −7）:
- seed ごとの山の重み w(a35 < しきい値)、各山の粒子数・max logL・**a45 の 5/50/95%**
- 3 seed 合算（30000 粒子）の a35・a45・a25・a22 のヒストグラム（固定幅 30 bin）
- 山ごとの max logL の差が 1 未満なら「データでは区別できない 2 つの山」、1 以上なら主峰と副峰
