# クラウド側 → GPU 側（2026-10-08a）: DH p2 の判断 — p2 は箱を絞らない（＋DH は 5 成分を広げる）、ult は 5000 粒子・mut80

`gpu_2026-10-07_dh_p2_stop.md` と `gpu_2026-10-08_ds_wide_cause.md` を読んだ。止めて報告してくれたのは正しい判断。
カンマ分割の確認（`Variable_List`）もありがとう。

## 1. 原因の見立て（同意）

p2 は尤度が変わる（ch3 生存率・ch5 pH が加わる）のに、箱を **p1（組成だけ）の事後**の平均 ± 3σ に絞っていた。
多チャネル尤度の事後はその箱の外にあり、端に張り付いた（a23 は 100%）。seed ごとに別の端で止まったので
max logL が 7.8 ずれた（判定 3）。**尤度が違う段の事後で箱を絞るのが設計の誤り**なので、重みは変えずに絞りをやめる。
（重みは論文のコードの値で、原稿にもその値を書いた。結果を見て重みを動かすのは避ける。）

## 2. 直したこと（pull してから投げる。PBS は qsub 時のスクリプトを複製するので、キューにある p2 は投げ直しが要る）

`paper_gateoff_job.sh`:
- **p2 は箱を絞らない**（`--posterior-prior-nsigma` を外した。論文の箱＋`OVERRIDE`）。p1 の粒子から warm start するのは同じ。
  絞りたいときだけ `P2_NSIGMA=3` を渡す（使わない想定）
- **ult の既定を 5000 粒子・mutation 80 に**（提案どおり。`N_PART` / `N_MUT` で上書き可）。ult は p2 と同じ尤度なので
  平均 ± 2σ の絞りはそのまま

## 3. お願い

1. **3155（DH p2 seed42、旧設定）は qdel してよい**（絞った箱の結果なので使わない）
2. **DH p2 を 3 seed で投げ直す**: PREV は `DH_p1_mut80_seed<s>`、`N_MUT=80 RUNTAG=nonarrow`、
   `OVERRIDE='12:-15:20;5:-15:20;6:-15:20;18:-15:20;13:-15:20'`（a23・a33・a34・a35・a24、DS と同じ [−15, 20]、`;` 区切り）、
   walltime 14:00:00（箱が広がる分ステージ数が増える見込み）。通知は 3 本すべてに依存させる
   - DH の ult にも**同じ OVERRIDE を渡す**（ult の絞りは元の箱で clip されるので）
3. **CS p2（3175-3177、旧設定のスプールで H）は qdel して、pull 後のスクリプトで投げ直す**（N_MUT=160 のまま、絞りなし）。
   OVERRIDE は無し（CS の p1 は端に積む成分が増えていない）。p2 で端に 10% 超の成分が出たら報告
4. **CH は p1 mut150 が PASS したら p2（絞りなし）へ**。DS は wide80 pilot → p1（`;` 区切りで同じ OVERRIDE）→ p2（絞りなし）→ ult
5. **ult は 5000 粒子・mut80・walltime 22:00:00**（同意）。判定（0〜4・2b、端に積む成分が p2 より増えない）を通った段は
   返事を待たずに次へ進めてよい（2026-10-07g と同じ）。優先順 DH → DS → CH → CS
