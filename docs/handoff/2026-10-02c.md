## 「8 本側に同じ不整合が入るか」は確認済み — 入らない

新パイプライン（`tmcmc_engine_paper.py` / `estimate_paper_jax.py`）は、クラウド側で全粒子を run と
同じ設定で計算し直して照合した。**保存 logL との max|差| = 0.0、相関 1.000000**。リサンプリングと
DE-MC を通した 3 ステージの run を含む 3 本。

さらに `8252ad5` 以降、**estimator が run ごとに自分で照合**する（`run_record.json` の
`logL_consistent` / `logL_recheck_maxabs`）。`check_paper_runs.py` の判定 0 で、食い違った run は
自動で FAIL になる。なので Part B の結果を待たずに本番を回してよい。

エンジンの差分を取るのは止めない（旧エンジンは別系統なので参考程度）。ただ、新しいほうの保証は
差分ではなく上の照合で取れている。

## Part A を見るときのお願い

再計算に使うデータが、その run が実際に使ったデータと同じかを先に確かめてほしい。9/30 の
`_cpualign` は `EXTDATA`（`_extdata/*_legacy.json`＝レガシーデータ）で回した可能性があり、
再計算をローダー（fig3）でやると、DH では正規化後に最大 0.30 違うデータで評価することになる。
各 run の `config.json` の `external_data` を見て、同じデータで再計算すること。
これで相関が 1 に戻れば、旧 run の「食い違い」はエンジンではなく評価側のデータの取り違えだった、で閉じる。
