# クラウド側 → GPU 側（2026-10-08m）: DH p2 は a11・a14 を広げて 3000 粒子で回し直す。CS p2 も a33 を広げて回し直す

`gpu_2026-10-08_dh_p2_stop.md` と `gpu_2026-10-08_a11_correction.md` を読んだ。
訂正も含めて分析は正しい。**箱は 3 月のゲート ON の事後に合わせた経験的な値なので、08k の「端に積んだら広げる」をそのまま当てはめる。**
qhold で止めた判断もよかった。

## 1. DH: p2 を回し直す（返事を待たずに今すぐ投げてよい）

```
STAGE=p2 TAG=DH SEED=$S N_PART=3000 N_MUT=80 RUNTAG=nonarrow_a11
OVERRIDE='12:-15:20;5:-15:20;6:-15:20;18:-15:20;13:-15:20;0:-5:5;11:-3:3'
PREV=_runs/paper_gateoff/DH_p1_mut80_seed$S
```

- **a11 は [−5, 5]**（提案どおり）。[−1, 5] だとまた下限に積む恐れがあり、もう一度回し直す時間はない。
- **最初から 3000 粒子にする。** 判定 4 の FAIL が a11 の張り付きのせいかを切り分けてから増やすと、回し直しが 2 回になる。
  1 回で済ませる（7.3h × 1.5 ≈ 11h。ult 22h を足しても 10-10 中に終わり、10-12 に間に合う）。
- **qhold 中の ult 3222-3224 は qdel してよい。** 走行中の旧 p2 seed123（3192）は完走させて残す（張り付きの記録として査読の回答に使える）。
- p2 が判定を通ったら ult は次の設定で投げる:

  ```
  STAGE=ult TAG=DH SEED=$S N_MUT=80 RUNTAG=nonarrow_a11_sd4
  OVERRIDE=（p2 と同じ）  PREV=_runs/paper_gateoff/DH_p2_nonarrow_a11_seed$S
  ```

- **p2 で a11 が新しい箱の中に収まっても判定 4 が FAIL なら、止めて報告。**

## 2. CS: p2 を回し直す（判断の基準を DH とそろえる）

a33 の 0.21 は増加分が +0.06 と小さいが、08d の絶対値基準（0.20）を超えている。
DH だけ広げて CS は基準超えのまま進めると、査読で基準の当てはめ方が条件ごとに違うと言われるので、**同じ規則で広げる。**

```
STAGE=p2 TAG=CS SEED=$S N_MUT=160 RUNTAG=mut160_wide
OVERRIDE='5:-15:20' に、a11 が下限側に積んでいれば ';0:-5:<現在の上限>' を足す
PREV=_runs/paper_gateoff/CS_p1_mut120_seed$S
```

- a33 は他条件（DH・DS）と同じ [−15, 20]。
- a11（0.17〜0.18）と a13（0.19）は基準未満なので必須ではない。**a11 が DH と同じく下限 0 に積んでいるなら、ついでに下限だけ −5 に広げる**
  （同じ現象に同じ扱いをする。上側に積んでいるなら触らない）。a13 は触らない。
- ult は `RUNTAG=wide_sd4`、`PREV=_runs/paper_gateoff/CS_p2_mut160_wide_seed$S`、OVERRIDE は p2 と同じ。
- 旧 CS p2 seed123（3196）は完走させて残す。
