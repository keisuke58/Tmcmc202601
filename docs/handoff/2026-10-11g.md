# クラウド側 → GPU 側（2026-10-11g）: CH だけ「初期値 Day 3」で pilot → ult を回す（ユーザー判断）

10-11f の診断で、CS の当てはまりの悪さの主因は初期値と分かった（Day 1→3 の So 18% → 70% をモデルが追えない。同じ θ で初期値だけ Day 3 にすると Day 6〜21 の RMSE 0.161 → 0.085）。
4 条件そろえて初期値を Day 3 にする案の前に、**ユーザー判断でまず CH だけ試す**（CH が悪化しないことを確かめてから DS・DH・CS に広げる）。

## 1. コードの変更（pull すれば入る）

- `estimate_paper_jax.py --ic-day N`（既定 1 = 今までどおり）: Day N の組成（正規化）を初期値にし、Day N を t=0 に置いて、それより後の日だけで当てる。day_scale は変えない（s = 0.2375 ↔ 21 日のまま）。pH の idx も同じだけずらす（λch5=0 なので効かない）。
- `paper_gateoff_job.sh`: `IC_DAY`（既定 1）を `--ic-day` に渡す。**連鎖の全段で同じ値。**
- `tools/eval_paper_runs.py`: run_record の `ic_day` を見て、同じ日・同じ idx で RMSE を出す（クラウドで照合 OK を確認済み）。
- `make_paper_figures.py` はまだ Day 1 前提。図にするのは 4 条件そろえると決めてから直す。

## 3. 判定と比べ方

- 判定は今までと同じ（0〜4・2b・片側の端）＋ **組成 RMSE < 0.1**。
- **比べる相手は今の CH 最終の Day 6〜21 の RMSE = 0.0704**（Day 3 を含む 0.0756 ではない。Day 3 は初期値になって当てる対象から外れるので、同じ日で比べる）。
  クラウドで計算済み: 今の CH MAP は Day 6〜21 で 0.0704、同じ θ で初期値だけ Day 3 にすると 0.110（θ が Day 1 初期値用なので当然。回し直しで下がるかを見る）。
- 報告してほしいもの: 3 seed の判定、RMSE（Day 6〜21）、種ごとの RMSE、生存率の予測と実測、同定される成分が今の CH（a11・a12・a22・a33・a13・a23）と変わるか、Pg の D21/D15。

## 4. その後（クラウド・ユーザーで判断）

- CH ic3 の RMSE ≤ 0.07 程度で判定 PASS → 4 条件そろえて ic3 に切り替える案をユーザーに出す（CS・DS・DH も pilot から）。
- CH ic3 が明らかに悪化 → ic3 はやめ、CS は手順そのままで限界として書く案に戻る。
